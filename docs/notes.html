Project orientation & codebase state

2026-05-17

The symbolic/compiled mode (Symbol + Compiler + Executor) is the only active codebase. The old eager mode (Tensor + Engine) is a deprecated prototype — files have been moved to autograd/eager/ and should not be treated as reference or oracle.

Symbolic pipeline — what's done

  • symbol.py — full operator-overloaded graph builder, mirrors the old Tensor API
  • compiler.py — optimization pipeline: canonicalization, constant folding, add/mul flattening, algebraic simplification, dead code elimination, decanonicalization
  • Executor.py — forward execution of a compiled topo list, with selective caching

Known bugs / incomplete

  • Compiler._accumulate() — reassigns a local variable instead of mutating, so gradients never accumulate
  • Executor.forward() caching condition — fixed, now uses index == len(topo) - 1
  • compile_backwards() — SOFTMAX case references undefined axis variable
  • Executor.backward() — resolved: not needed (see s3)

Executor fixes & design decisions

2026-05-18

Bugs fixed in Executor.py

  • ADD and MULTIPLY cases had no return results — silently returned None at runtime. Fixed by adding explicit returns.
  • GREATER_THAN / LESS_THAN used np.all(), collapsing the comparison to a single scalar boolean. Fixed to return element-wise boolean arrays (inputs[0] > inputs[1]), consistent with all other shape-preserving ops.
  • SIZE was a stub (pass). Fixed: now uses np.size(inputs[0], kwargs.get('axis')) wrapped as a 0-d np.ndarray. The original broken version wrapped in a list, producing a 1-element 1-D array instead of a scalar.

Type annotation fixes

  • _eval_node return type changed from NonSymbolInputs to np.ndarray — every branch either returns an array or raises.
  • _get_value return type changed from NonSymbolInputs to np.ndarray — it hits the cache (typed Dict[int, np.ndarray]), returns node.value after a is not None guard, or raises. Never returns None.
  • inputs: list[np.ndarray] annotation in _eval_node is now correct given the above.

Key design decision — no Executor.backward()

Compiler.compile_backwards() symbolically differentiates the forward graph and produces a new topo list of Symbol nodes representing the gradient computations. That gradient graph is structurally identical to a forward graph, so Executor.forward() executes it directly — no separate backward() method is needed or appropriate. This is a fundamental property of symbolic differentiation: the backward pass is a forward pass over a different graph.

Eager mode status

Deprecated. Files moved to autograd/eager/. Do not use as a reference oracle or test target going forward — all new tests should target the symbolic pipeline.

Test suite migration & bugs found

2026-05-18

Migration

  • autograd/__init__.py updated to export the symbolic API (Symbol, Compiler, Executor). autograd/eager/__init__.py created so the eager subpackage is importable.
  • autograd/eager/tensor.py import fixed: from .ops → from ..ops (ops lives in the parent package).

New symbolic test suite — 130 tests

  • tests/test_symbol.py — graph construction, operator overloads, requires_grad inference
  • tests/test_compiler.py — constant folding, algebraic simplification, canonicalization/decanonicalization, DCE, end-to-end value correctness
  • tests/test_executor.py — forward pass for every operation; also added missing BROADCAST_TO_MATCH and UNBROADCAST cases to Executor._eval_node
  • tests/test_backward_symbolic.py — analytical gradients vs central finite differences for every op

Bugs found by the test suite (all marked xfail)

  • NEG backward missing — _backwards_node has no NEG case. Decanonicalization converts MULTIPLY(-1, x) → NEG, so any subtraction whose second operand requires grad silently drops its gradient. Fix: add case Operation.NEG: arg.grad = _accumulate(arg.grad, -grad).
  • SQRT backward missing — no SQRT case in _backwards_node. Affects x.sqrt() and x ** 0.5 (both decanonicalize to SQRT). Fix: arg.grad = _accumulate(arg.grad, grad / (2 * node)).
  • TRANSPOSE backward missing — no TRANSPOSE case. Fix: arg.grad = _accumulate(arg.grad, grad.transpose()).
  • RESHAPE / EXPAND_DIMS / SQUEEZE / SWAP_AXIS backward missing — none of these shape ops have backward cases. Fixes are straightforward inverses: reshape back, squeeze/expand, swap axes again.
  • MATMUL backward uses * instead of @ — compiler.py line ~658: grad * b.transpose() and a.transpose() * grad should both use @. Element-wise multiply produces wrong shapes and wrong values.
  • SUM / MEAN axis backward incomplete — after expand_dims the gradient is not broadcast back to the input shape, so the gradient has the wrong shape for axis reductions without keepdims.
  • DCE ordering bug (compiler) — when _algebraic_simplification eliminates the root node (e.g. log(exp(x)) → x), it removes it from new_topo without ensuring the replacement is last. DCE then selects the wrong node as the live root. Workaround in tests: wrap root-level simplifications in an outer .sum().

Backward pass — all bugs fixed

2026-05-19

New operation: RESHAPE_LIKE

Added RESHAPE_LIKE(x, ref) to ops.py, symbol.py, Executor._eval_node, and Compiler._eval_map. Mirrors the BROADCAST_TO_MATCH / UNBROADCAST pattern: uses the runtime shape of ref so the original shape doesn't need to be known at compile_backwards time. Its own backward is grad.reshape_like(inp) — it is its own inverse.

Fixes in _backwards_node

  • RESHAPE — grad.reshape_like(inp)
  • EXPAND_DIMS — grad.squeeze(axis) (axis known from kwargs)
  • SQUEEZE — grad.expand_dims(axis) for specified axis; grad.reshape_like(inp) for axis=None
  • SWAP_AXIS — grad.swap_axis(axis1, axis2) (its own inverse)
  • SUM axis backward — added .broadcast_to_match(inp) after expand_dims; the expanded gradient was previously left at the reduced shape instead of being broadcast back to the full input shape. This fix also unblocked the MEAN axis backward (which received a correctly-shaped upstream gradient as a result).
  • ADD broadcasting — changed grad → grad.unbroadcast(p) for each ADD input. Without this, broadcasting across an ADD (e.g. x - x.mean(keepdims=True)) passed the full-shaped gradient to a smaller-shaped node, producing wrong gradients.
  • NEG / SQRT / TRANSPOSE requires_grad guard — these three cases accumulated gradients without first checking prev[0].requires_grad.

MATMUL 1D input fix (Executor)

W @ x where x is 1D (shape (k,)) works in the forward pass. In the backward, grad_W = grad @ x.T fails because numpy's transpose of a 1D array is a no-op, so the executor received (m,) @ (k,) — an invalid matmul. The correct result is np.outer(grad, x). Fix: in Executor._eval_node MATMUL case, when both inputs are 1D, use np.outer instead of @.

DCE ordering bug fixed

2026-05-19

The bug

When _algebraic_simplification eliminated the root node (e.g. log(exp(x)) → x), it removed the root from new_topo without ensuring the replacement ended up last. _dead_code_elimination always treats topo[-1] as the live root, so it picked the wrong node — in the log(exp(x)) case, EXP(x) ended up last and was treated as the root, so the executor returned exp(x) instead of x. The bug was order-dependent: x + 0 passed by coincidence (x was last) but 0 + x failed (0 was last).

The fix

After the simplification loop in _algebraic_simplification, resolve the actual root via get_actual(topo[-1]) and move it to the end of new_topo if it isn't already last. DCE then correctly identifies the replacement as the live root and eliminates the now-dead intermediate nodes (e.g. EXP(x)).

Note on non-adjacent inverses

This fix only applies after a simplification rule fires. It does not handle cases where f and f⁻¹ are not directly composed (e.g. log(c * exp(x))). Local rewrite rules require the pair to be structurally adjacent; general inverse cancellation through commutative or associative operations would require a more powerful approach (e.g. e-graphs / equality saturation).

Test cleanup

Removed .sum() wrappers and the workaround comment from tests/test_compiler.py. Root-level simplification tests (log(exp(x)), T(T(x)), 0+x, etc.) now assert directly on the simplified value.

7

Next steps

2026-05-19

The symbolic backend is complete and fully tested. Priorities for what comes next:

1 — User-facing API (highest priority)

The library has no usable interface. To compute a gradient today you must manually call Compiler.compile(..., backwards=True), Executor.forward(), compiler.compile(sym.grad), and Executor.forward() again. The goal is a grad(f) function that hides all of this.

Design: grad(f) is the expensive step — it uses inspect.signature to determine how many arguments f takes, creates one VARIABLE Symbol per argument, calls f(*syms) to trace the graph (no values needed — operator overloads build the structure), compiles the forward graph, runs compile_backwards, and compiles each gradient graph. All compiled topos are captured in a closure.

The returned df(*values) is cheap — it just runs executor.forward on the pre-compiled forward topo (to populate node values), then runs executor.forward on each pre-compiled gradient topo, and returns the list of gradient arrays. No recompilation on each call.

2 — ABS backward missing

Every differentiable op now has a backward rule except ABS. Gradient is sign(x) — a one-liner to add to _backwards_node.

3 — End-to-end workload validation

The test suite verifies individual ops numerically but nothing has been run as a full training loop. Fitting a linear regression or a small MLP (forward + backward + gradient descent update) would surface any integration bugs that unit tests miss.

4 — Executor copy mode

executor.forward currently sets node.value in-place on Symbol objects shared between the forward and gradient topos. A future copy=True parameter would write results only to self._cache and leave node.value untouched, so grad evaluations never corrupt forward node values between calls. Deferred until after the user-facing API is in place.

5 — Longer term

  • Second-order gradients — the infrastructure is clean enough that differentiating through the gradient graph is feasible, but needs the user-facing API to be solid first.
  • Optimizer primitives — SGD, Adam etc. are just graph operations, but depend on the API wrapper to be useful.

grad API, SIGN op, ABS backward fix

2026-05-19

grad API — autograd/grad.py

grad(f) is the compile-time step: uses inspect.signature to determine the number of arguments, creates one VARIABLE Symbol per argument, calls f(*syms) to trace the graph (no values needed — operator overloads build structure), compiles the forward graph with backwards=True, and compiles each input's gradient graph. All topos are captured in a closure.

Returns (df, evalf). df(*values) runs forward once to populate node values, then evaluates each pre-compiled gradient topo — no recompilation per call. evalf(*values) just runs the forward topo. Exported from autograd.__init__.

SIGN operation

  • Added SIGN = 33 to ops.py
  • Added sign() method to Symbol
  • Added np.sign to Executor._eval_node and Compiler._eval_map
  • SIGN backward is pass — sign(x) is piecewise constant, gradient is zero everywhere

ABS backward bug fix

The ABS backward was grad.sign() — this computed sign(upstream_gradient) instead of sign(x). The correct gradient of |x| is upstream_grad * sign(x). Fixed to grad * inp.sign().
